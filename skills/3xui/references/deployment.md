# 部署与维护要点

## 来源与历史适用范围

本 skill 提炼自 2026-10-30 的「3xui devops」「安装3xui到当前目录」会话，以及部署留下的需求、节点、当前状态与运维文档。未收录原始会话、凭据、订阅链接、数据库或服务器地址。

当时的组合为 3x-ui v3.11.0、Xray 26.10.21、Mihomo v1.19.33、Rocky Linux 9.8/x86_64。此信息仅用于理解历史兼容问题，不能证明当前推荐版本或其他平台的支持状态。新任务应从以下官方入口重新核实：

## 安装选择和网络

识别 OS/架构、资源、已安装的 Docker/Compose 或原生服务、现有端口、SELinux 和防火墙。保留可用运行时；需要安装或更新时使用官方支持的新稳定版本，不为了新建面板无条件升级其他服务依赖。

核实选定发布的 Dockerfile、示例 Compose、镜像来源、默认端口和实际 Xray 版本。官方示例可能使用 host 网络或额外权限，不照搬为必需条件。

分别列出三类入口：

| 入口 | 应核实 |
| --- | --- |
| 管理面板 | 应用监听、宿主机绑定、管理路径、认证及 TLS |
| 订阅服务 | 独立监听、HTTP/HTTPS、SUB/CLASH 开关、映射和外部入口 |
| 代理入站 | 真实 TCP/UDP 协议、端口、桥接映射或 host 监听、云侧放行 |

更改某个入口不代表其他入口已配置。历史环境使用过面板 2053、订阅 2096 和节点 TCP 443；这些只是案例值，不据此占用新机器端口。不能因为旧安装脚本曾生成某个随机端口就认定当前端口相同。

首次仅本机管理时使用 SSH 隧道。用户已授权公网管理则实现其需求，并明确实际 TLS 状态。防火墙、云安全组、IPv4/IPv6 分别核实；不要关闭整机防火墙、SELinux 或清理无关规则。

## 数据和配置来源

按需使用以下布局，Compose 留根目录：

```text
~/app/3xui/
├── compose.yaml
├── .env / .env.example
├── config/              # 非敏感配置及维护副本
├── data/db/             # 面板数据库及实际持久化数据
├── secrets/
│   ├── admin.json       # 管理员凭据及私密访问方式
│   ├── cert/            # 证书、私钥
│   └── clients/         # 敏感客户端静态导出
├── backups/
├── scripts/             # 有实际用途时创建
└── docs/
```

选定版本的容器内部路径以镜像实际定义为准。历史镜像使用数据库目录 `/etc/x-ui`、证书目录 `/root/cert`；如适用 SELinux，保留正确的挂载标签，不以禁用 SELinux 替代排查。

普通凭据文件 0600、敏感目录 0700；备份同样包含秘密。凭据文件不保证自动同步面板内的改密，必须明确其维护方式。发现凭据曾被公开时按实际授权进行轮换，并验证新值生效、旧值失效；不再次输出新值。

业务设置通常由面板数据库管理。通过对应版本的面板/API 修改，先确认路径前缀、认证、Cookie/CSRF、设置字段与序列化格式，不硬套旧版本请求。读取现有设置，只更新目标字段并保留其他设置；不把整份响应或 Cookie 输出到聊天。

记录配置优先级：Compose/.env 管理容器参数；面板数据库管理业务设置；`config/` 中的规则文件可能只是维护副本；`secrets/clients/` 是静态快照。只有存在已验证的同步机制时，才宣称改文件会改变面板或自动导出。

## 一致性备份、升级和迁移

先记录当前固定镜像、数据库位置、挂载、端口、敏感文件和恢复方式。使用软件支持的在线备份，或在停服务窗口备份数据库、配置和凭据；不能直接复制写入中的 SQLite 文件当作一致性备份。

升级时核实发布说明与数据库迁移，保存旧镜像引用和匹配的数据备份。修改固定版本后验证登录、原入站/客户端、订阅、真实代理与持久化。回滚可能需要旧镜像与旧数据库一起恢复。

迁移目录前核对所有 Compose 挂载、脚本、忽略规则和文档；备份后按需停服务，迁移并同步引用。核对数据一致性和容器实际挂载，再验证功能。历史日志保留旧路径并追加映射，当前运维手册只保留生效路径。

禁止用删除数据库、`docker compose down -v` 或重复初始化解决已有部署问题。备注修改和一般客户端变更不例行重启；全局设置、订阅设置是否需重载按当前版本机制决定，应用后验证。不要为例行验证重启整台主机。
