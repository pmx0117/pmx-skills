# 部署文档交付约定

这些文档保存在被安装软件的 `~/app/<软件名>` 下，不是 skill 自身的项目说明。写实际结果，未完成的内容标注“待执行”“未验证”或“未知”，不要保留看似完成的空模板。

## AGENTS.md：维护入口

记录以下信息即可，不复制完整运维手册：

- 本目录的用途及绝对路径；部署目录与上游源码的区别。
- 后续维护前读取 README.md、docs/current-state.md、docs/requirements.md、docs/operations.md。
- 数据、配置、备份及凭据位置；说明敏感值不能回显或提交。
- 实际采用的版本固定方式、维护限制、适用的系统差异。
- 不可破坏的数据和必须保留的配置；哪些危险操作不能自动执行。
- 必需的配置/脚本检查，以及变更后更新当前快照、需求状态及日志。

项目特有规则应来自实际架构和用户要求，不把单个产品的端口、协议、服务名称推广成所有部署的通用规则。

## README.md：一分钟了解部署

写明软件用途、部署路径、当前状态、非敏感访问方式和文档链接。明确服务是否已经启动、核心功能是否验证。凭据只引用存储路径，不贴值。

不要同时维护另一套详细版本和配置表；版本及运行配置引用 current-state.md。

## docs/current-state.md：权威当前快照

在文件开头记录最后核实时间和时区。覆盖实际适用项：

| 类别 | 必须能回答的问题 |
| --- | --- |
| 状态 | 准备中、已安装、运行中、受阻还是部分可用？哪些项目尚未验证？ |
| 主机 | OS/架构、相关资源约束、检查是否来自宿主机或沙箱？ |
| 版本 | 应用精确版本、镜像 tag/digest 或软件包版本、官方来源、核实时间？ |
| 依赖 | 运行时、Compose、数据库、核心引擎、必要插件的实际版本？ |
| 兼容性 | 用户设备/客户端外壳与内核版本？测试过什么格式、参数与功能？ |
| 启动 | 部署方式、工作目录、服务/容器名称、启动策略、健康检查？ |
| 网络 | TCP/UDP、容器端口、主机映射、绑定地址、公网/本机、域名及 TLS 状态？ |
| 配置 | 配置入口、关键非敏感值、环境/文件/数据库/API 的覆盖优先级？ |
| 数据 | 持久化路径、挂载、权限、目录外的系统依赖和修改？ |
| 安全 | 凭据存放路径及权限、访问控制、未完成的认证/TLS 配置？ |
| 功能 | 用户需要的功能开关、独立监听、生成配置、路由及导出状态？ |
| 备份 | 最近有效备份位置/时间、备份范围、恢复约束？ |
| 证据 | 哪些验证何时通过？本机检查与真实外网/设备实测分别如何？ |
| 待办 | 尚未处理的需求、阻塞原因、下一步及影响？ |

不记录密码、私钥、订阅令牌、带凭据 URL 或完整 .env。访问地址含敏感路径或 token 时只描述构成并引用私密文件。

有多个配置来源时写出事实，例如：“面板数据库为运行源；config/foo.yaml 是人工维护副本，改文件不会自动写回面板；导入文件是静态导出”。避免后续维护者修改错误入口。

## docs/requirements.md：需求和决策

用简短表格维护：需求、来源/确认时间、实现方式、当前状态、验收证据/限制。

区分用户明确要求、已接受的方案、尚未确认的假设。记录公网访问、目录、软件版本偏好、目标客户端和核心业务行为。新消息补充需求时更新；被替代的需求标记已替代，不能仍被当作当前约束。

这份文档不是聊天全文，也不将代理建议自动记作用户已确认的要求。

## docs/operations.md：按当前实际配置执行

针对本项目提供可执行的方法，而非照抄所有操作系统安装命令：

1. 当前前置条件、安装来源、选定方式、配置位置及重建步骤。
2. 日常查看状态、重载/重启/停止和日志诊断；提示日志可能包含秘密，不直接复制到聊天。
3. 修改常见设置的正确入口，何时生效，静态客户端输出如何重新生成。
4. 一致性备份及恢复步骤、目录和权限；恢复前检查内容及现有状态。
5. 固定版本升级、迁移验证和回滚，说明是否需要恢复匹配版本数据库。
6. 本项目真实遇到的故障定位：服务端与客户端、格式与协议、网络与权限边界。

步骤依赖证书、域名、外部数据库或离线资源时说明条件。不要通过复制示例命令覆盖已有配置和数据。

历史方案移入 deployment-log.md；操作手册以当前配置为准，必要的备选方案标注适用条件。

## docs/deployment-log.md：追加记录

每次安装或实际部署变更记录：

- 时间与时区、触发需求、完成了什么。
- 原版本/配置到新版本/配置的非敏感变化。
- 备份及回滚入口、系统级改动或临时中断。
- 验证结果、验证范围、失败与剩余事项。

只保留定位或维护有用的事实；不要把历史状态描述成当前状态，也不要粘贴完整敏感配置或原始日志。

## 交付前核对

文档中的版本与运行实例一致；端口与实际绑定一致；功能状态与真实开关一致；脚本和运维命令使用当前文件；所有已知限制进入当前快照。检查多个文档是否仍存在相互冲突的“当前状态”。

## 推荐部署布局

根目录保留 AGENTS.md、README.md、compose.yaml、.env、.env.example、.gitignore。非敏感配置置于 config/，持久化数据置于 data/，凭据、私钥及敏感客户端文件置于 secrets/，备份放 backups/，运维脚本放 scripts/，交接文档放 docs/。只创建实际需要的目录，原生部署不必生成 compose.yaml。当前快照应给出实际目录树和容器挂载映射。
